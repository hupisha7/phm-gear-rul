## W15 · NASA C-MAPSS（学会标准流程）

### 为什么先做这个

C-MAPSS 是 **PHM 领域的标准基准数据集**，几乎每篇 RUL 论文都用它：
- **有公认的、明确的 RUL 标签**（不像你的 UNSW 数据）
- 数据量小（几十 MB），下载快
- 有公开的评测协议和 baseline 结果

**用它学会"标准 RUL 流程"长什么样，再回到你的难题上。**

### 数据

- 下载：NASA Prognostics Center of Excellence 官网（搜 "C-MAPSS turbofan degradation"）
- 或 Kaggle 搜 "CMAPSS Jet Engine Simulated Data"
- 四个子集：FD001–FD004，从 **FD001** 开始（最简单）

### 概念

| 概念 | 要点 |
|---|---|
| RUL 标签怎么来 | 训练集给的是"到失效还剩多少循环"，直接可得 |
| **piecewise linear RUL** | 早期 RUL 封顶（如 125），因为早期看不出退化 |
| 滑动窗口 | 把时序切成固定长度窗口作为样本 |
| 传感器选择 | 有些传感器是常数，要剔除 |

### 代码任务 `src/w15_cmapss.py`

**任务 1 · 跑通标准流程**
1. 读数据（空格分隔的 txt）
2. 剔除常数传感器（方差 ≈ 0）
3. 按 piecewise linear 构造 RUL 标签
4. 滑窗切样本
5. 训练一个简单模型（先 LSTM 或 1D-CNN）
6. 在测试集上算 RMSE

**任务 2 · 复现一个 baseline**
- 找一篇用 C-MAPSS FD001 的论文，看它的 RMSE 是多少
- 对比你的结果（经典 baseline RMSE 在 **12–18** 左右）

### 产出

- `src/w15_cmapss.py`
- `results/w15_cmapss_pred.png`
- 一张表：你的 RMSE vs 文献 baseline

### 验收

1. 为什么 C-MAPSS 的 RUL 标签是"直接可得"的？和 UNSW 数据的根本区别是什么？
2. 为什么要做 piecewise linear（封顶）？
3. 你怎么判断一个传感器该不该保留？

## W18 · 不确定性量化（工业可用性的分界线）

### 为什么这是分界线

**学生作业**：给出一个 RUL 数字 → "还剩 37.2 小时"
**工业方案**：给出一个区间 → "还剩 37.2 小时，95% 置信区间 [25, 52]"

**只说一个数字的 RUL 预测，工业界不敢用。** 因为维护决策需要知道风险。

### 三种方法（选一种，推荐 A）

#### 方法 A · MC-Dropout（最简单）

```python
# 推理时保持 dropout 打开，前向传播 N 次（如 100 次）
model.train()          # ← 关键：不是 model.eval()
preds = [model(x) for _ in range(100)]
mean = preds.mean()
std  = preds.std()
ci95 = (mean - 1.96*std, mean + 1.96*std)
```

**只需要改 3 行代码。**

#### 方法 B · Deep Ensemble

- 训练 5 个不同初始化的模型
- 用它们的预测分布作为不确定性

#### 方法 C · 分位数回归

- 损失函数换成 pinball loss，直接输出 P10 / P50 / P90

### 代码任务 `src/w18_uncertainty.py`

**任务 1 · 实现 MC-Dropout**
**任务 2 · 画带置信区间的 RUL 预测图**
- 中间：预测均值
- 阴影：95% 置信区间
- 黑线：真实值

**任务 3 · 评估区间质量**
- **PICP**（预测区间覆盖率）：真实值落在区间内的比例，应该接近 95%
- **MPIW**（平均区间宽度）：越窄越好

**任务 4 · 观察关键现象**

> **理想情况：越接近失效，置信区间越窄。**
> 因为数据多了、退化趋势明确了。
> 如果你的区间在后期反而变宽，说明模型有问题。

### 产出

- `src/w18_uncertainty.py`
- `results/w18_rul_with_ci.png`（⭐ 带置信区间的预测图）
- PICP / MPIW 报告

### 验收

1. 你的 PICP 是多少？接近 95% 吗？
2. 置信区间随时间是变宽还是变窄？为什么应该变窄？
3. MC-Dropout 为什么能估计不确定性？（提示：dropout 相当于近似贝叶斯采样）

## W19 · 跨工况迁移（解决你毕设承认的弱点）

### 为什么做这个

你毕设在"不足与展望"里写了：

**把它做掉，这就是一个真正的贡献。**

### 任务设置

| 实验 | 训练 | 测试 |
|---|---|---|
| A（基线） | 润滑 | 润滑（同域） |
| B（跨域） | 润滑 | **干摩擦** |
| C（微调） | 润滑 → 干摩擦少量样本微调 | 干摩擦 |
| D（域适应） | 润滑 + 干摩擦（无标签对齐） | 干摩擦 |

**关键难点**：两个工况的转速、载荷、润滑、总时长都不一样（16 Hz/20 Nm/67 h vs 10 Hz/5 Nm/2.4 h）。

### 代码任务 `src/w19_transfer.py`

**任务 2 · 标准化对齐**

**任务 3 · 微调**
- 用干摩擦的前 2 个文件微调，后 8 个测试

**任务 4（进阶）· 域适应**
- 简单方法：MMD 损失 或 对抗域适应
- 目标是让两个工况的特征分布对齐

### 产出
