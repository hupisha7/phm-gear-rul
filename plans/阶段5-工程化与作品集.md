## W21 · 工程基础（Git / Linux / Docker）

### 为什么现在学这个

前面几个月你已经天天在用 Git（双机同步）。现在把它**系统化**，并补上 Linux 和 Docker。

**为什么 PHM 岗位要 Docker**：模型最终要部署到工控机/边缘设备/服务器上，必须能打包成一致的环境。这是"能交付"的标志。

### 学什么

| 主题 | 必须掌握 |
|---|---|
| **Git** | 分支、合并、`.gitignore`、`commit` 规范、`git log --oneline`、回滚 `git checkout` |
| **Linux** | `cd/ls/cp/mv/rm`、`grep`、`find`、`chmod`、管道 `|`、`ssh`、`nohup`、`tmux` |
| **Docker** | `Dockerfile`、`docker build`、`docker run`、`-v` 挂载、`docker-compose` |

### 代码任务

**任务 1 · 给项目写 `Dockerfile`**

```dockerfile
FROM python:3.10-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
CMD ["python", "src/w14_evaluate.py"]
```

**任务 2 · 生成 `requirements.txt`**
```powershell
pip freeze > requirements.txt
```
（或者手写一个干净的，只列真正用到的）

**任务 3 · 跑通**
```powershell
docker build -t phm-gear .
docker run --rm -v ${PWD}/results:/app/results phm-gear
```

**任务 4 · 练 Git 分支**
```powershell
git checkout -b feature/w21-docker
# 改点东西
git add -A; git commit -m "W21: 加 Dockerfile"
git checkout main
git merge feature/w21-docker
git push
```

### 产出

- `Dockerfile`、`requirements.txt`
- Docker 构建成功的截图或日志
- 至少合并过一次分支

### 验收

1. `docker build` 和 `docker run` 的区别是什么？
2. `-v` 挂载参数解决什么问题？
3. 为什么容器里的路径要用 `/app` 而不是 `C:\`？

## W24 · 监测看板

### 目标

### 两个选择

| 方案 | 难度 | 适合 |

| Grafana | 🔶 需要配数据源 | 更"工业风"，可以后面做 |

### 代码任务 `src/dashboard.py`

```python
import streamlit as st
import pandas as pd

st.title("齿轮健康监测")

# 1. 侧边栏选工况和文件
mode = st.sidebar.selectbox("工况", ["润滑", "干摩擦"])

# 2. 画 HI 趋势
st.subheader("健康指标 HI")
st.line_chart(hi_df)

# 3. 画 RUL 预测 + 置信区间
st.subheader("剩余寿命预测")
st.line_chart(rul_df)         # 含 mean / lower / upper

# 4. 显示当前状态
col1, col2, col3 = st.columns(3)
col1.metric("当前 HI", f"{hi_now:.3f}")
col2.metric("预测 RUL", f"{rul_now:.1f} 小时")
col3.metric("置信区间", f"[{low:.0f}, {high:.0f}]")
```

跑：

**改成：**

```
面向工业机器人关节齿轮的预测性维护算法研究

  齿轮 19/52 齿，干摩擦/润滑两工况，4 通道），构建齿轮剩余寿命预测系统。

· 【关键】在自检中发现原模型存在严重标签泄漏：规则先验分支与监督标签
  由同一公式生成（逐位相等，MSE=0），且采用随机划分导致同文件相邻窗口
  跨集合。移除泄漏后 gate 由 0.81 升至 0.94，直接证明模型在"抄答案"。
  改用物理健康指标标签 + 严格按文件顺序划分后重跑，R² 由 0.9991 降至
  X.XX —— 量化了泄漏导致的性能虚高程度。

· 构建无监督健康指标：融合时域（RMS/峭度/峰值因子）、频域（啮合频率
  190/304 Hz 及边频带）、包络谱、绝对传动误差共 12 项特征，经单调性/
  趋势性/鲁棒性三准则筛选，自编码器重构误差作 HI，单调性 |Spearman|=X.XX。

· 对比 RandomForest/XGBoost/SVR 与 CNN/CNN-LSTM，用 MC-Dropout 给出
  RUL 的 95% 置信区间（PICP=X%，MPIW=X 小时）。

· 工程化：Docker 打包、FastAPI 推理服务、Streamlit 监测看板。
```
